Implemented lifecycle rules

  • Regular selection uses active jobs, ONLY_EMPTY, and SITE_FILTER. Never-attempted or changed inputs run FIFO before due retries; repeated failures use persistent bounded exponential backoff. Explicit --redo N runs the newest N jobs and bypasses screening and backoff. Empty title and description do not consume LIMIT.
  • Stage 1 uses the configured resume and job evidence, respecting MAX_RESUME_TOKENS and MAX_JOB_DESC_TOKENS; a value of zero keeps full text. It returns only a provisional match_percentage and experience_match, requests thinking off, and starts with a 512-token output cap. Some installed templates still reason; truncation or invalid JSON can use one bounded 2048-token retry. Screen errors retain safe diagnostic metadata.
  • A valid preliminary score at or above AI_DEEP_ANALYSIS_MIN_MATCH (75 by default, inclusive) receives detailed analysis. Below-threshold jobs stay searchable without overwriting final scores or compensation. The preliminary score controls routing, not hiring decisions.
  • job_match_screens stores the score, experience classification, input fingerprint, and UTC screening timestamp separately from final AI fields. The fingerprint includes resume/job evidence, screen prompt/schema version, model, context, and token limits. Fresh below-threshold screens make no further model calls; threshold changes reroute a cached score without rescreening.
  • The coordinator saves valid screens when worker results return, including results whose detailed pass failed. Invalid screens remain pending for retry. A primary batch whose attempted jobs all fail reports failure and skips background Fit Brief generation. An unavailable Ollama server stops new submissions; queued calls are cancelled when possible and running calls finish.
  • Stage 2 assesses the complete detailed contract, including its own experience classification, compensation, fit summary, keywords, and location-policy match. Private review is configurable; invalid or failed reviews preserve the valid detailed result. Ollama outages preserve existing final fields.
  • Fit Briefs require active jobs meeting the final AI_FIT_BRIEF_MIN_MATCH (75 by default). Brief freshness depends on resume/job hashes and schema version.
  • The dashboard only queues Application Prep. The processor checks for it before and between bounded analysis batches and before each Fit Brief batch. Application Prep and Fit Brief stages publish heartbeats during bounded model waits, and completed priority work restores its parent stage and counters. Prep work interrupted by an Ollama outage or coordinator failure returns to queued. Active inference is not interrupted; newly queued work can wait for the current batch or a later run if it arrives as processing ends.
  • AI_CONCURRENCY=1, AI_MAX_INFLIGHT=1, and OLLAMA_KEEP_ALIVE=1m are the lower-demand defaults. Existing environment overrides take precedence. The model stays loaded during continuous work; shorter idle retention does not put the PC to sleep.
  • LIMIT applies after cached screen-outs, empty postings, and backoff-delayed failures are removed. Fresh work has priority, so with continuous arrivals and LIMIT=1, a due retry can still wait. Use one processor with the existing scheduled-run lock; these queues do not coordinate competing processor instances.
  • Grounded Application Prep drafts still require human approval before resume changes or artifacts are created. The dashboard coverage report includes deferred jobs without final analysis; screening decisions and cache counts are currently available in the processor log.

Future improvements

  • Measure wall power, inference time, and false negatives on representative jobs before tuning the threshold or adding an uncertain score band.
  • Show preliminary screening score, freshness, and a per-job Analyze anyway action in the dashboard. The current override is --redo N.
